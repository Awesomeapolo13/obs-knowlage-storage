## Использование команды /agents

Эта команда предоставляет интерактивный интерфейс для управления субагентами. После её запуска можно:
- увидеть все доступные субагенты (встроенные, пользовательские, проектные и из плагинов);
- создавать новых субагентов с управляемой настройкой или сгенерированных Клодом;
- править существующих субагентов (описание, доступ к инструментам);
- удалять кастомных субагентов;
- смотреть какие субагенты активны, когда доступны дубликаты.

Это рекомендованный путь, чтобы создать и управлять субагентами. Для ручного создания или автоматизации, можно так же добавлять субагентов как файлы напрямую в их папку.

Чтобы перебрать всех сконфигурированных субагентов из командной строки без начала новой интерактивной сессии, можно запустить `claude agents`. Это покажет агентов сгруппированных по источнику и пометит те из них, которые переопределены с помощью более высокого приоритета.

## Выбор области действия

Субагенты по сути это файлы макрдаун с вступлением в формате YAML. Их следует хранить в разных местах в зависимости от области видимости. Когда несколько субагентов делять одно и то же имя, выигрывает тот, у кого более высокий приоритете по размещению.


| Размещение                      | Область видимости      | Приоритет         | Способ создания                       |
| ------------------------------- | ---------------------- | ----------------- | ------------------------------------- |
| `--agent` CLI флаг              | Текущая сессия         | 1 (самый высокий) | Передать JSON при запуске Claude Code |
| `.claude/agents/`               | Текущий проект         | 2                 | Интерактивный или ручной              |
| `~/.claude/agents/`             | Все проекты            | 3                 | Интерактивный или ручной              |
| Плагинские `agents/` директории | Там где плагин включен | 4 (самый низкий)  | Устанавливается с плагинами           |

Проектные субагенты (`.claude/agents/`) идеальны для специфичной кодовой базы. Их можно помещать в систему контроля версий, таким образом вся команда сможет использовать и улучшать их.

Пользовательские (`~/.claude/agents/`) это персональные субагенты доступные во всех преоктах.

CLI-определяемые субагенты размещаются как JSON, при запуске Клода. Они существуют только для конкретной сессии и не сохраняются на диск, делая их полезными для быстрых тестирующих или автоматизационных скриптов. Можно определять множетсва субагентов за один вызов флага `--agent`:

```shell
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer. Focus on code quality, security, and best practices.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  },
  "debugger": {
    "description": "Debugging specialist for errors and test failures.",
    "prompt": "You are an expert debugger. Analyze errors, identify root causes, and provide fixes."
  }
}'
```

Субагенты плагинов приходят с установленными плагинами. Они появляются в списках, вызываемых командой `/agents`, вместе с кастомными субагентами. 

Плагинские субагенты, по присиным безопасности, не поддерживают такие поля как  `hooks`, `mcpServer` и `permissionMode`. Если эти поля необходимы, то скопируйте файлы плагиновского агента в `.claude/agents/` or `~/.claude/agents/`. Так же можно определить доступы в `permissions.allow` в `settings.json` или `settings.local.json`, но эти правила будут применены лишь внутри сессии, а не к плагинским субагентам.

## Написание файла субагента

Файлы субагентов используют ямл формат во вступительной части, затем следует системный промпт в формате маркдаун:

```markdown
---
name: code-reviewer
description: Reviews code for quality and best practices
tools: Read, Glob, Grep
model: sonnet
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.
```

Вступление (frontmatter) определяет метаданные субагента и его конфигурацию. Тело же становится системным промптом, который направляет поведение субагента. Субагенты получают только этот системный промпт (плюс базовые детали окружения, такие как рабочую директорию), но не полный системный промпт Клод Кода.

Во вступлении поддерживаются следующие поля, из которых обязательными являются только `name` и `description`.


| Поле              | Обязательно | Описание                                                                                                                                                                                                                                                                  |
| ----------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`            | +           | Уникальный идентификатор из букв в нижнем регистре и дефисов                                                                                                                                                                                                              |
| `description`     | +           | Условия при которых нужно делегировать работу этому субагенту                                                                                                                                                                                                             |
| `tools`           | -           | Инструменты, доступные субагенту. Если опущены, то наследует инструменты основного контекста                                                                                                                                                                              |
| `disallowedTools` | -           | Запрещенные инструменты, те что удаляем из унаследованных или основного списка инструментов                                                                                                                                                                               |
| `model`           | -           | Модель для использования: `sonnet`, `opus`, `haiku`, полный ID модели (например, `claude-opus-4-6`). По умолчанию наследуется.                                                                                                                                            |
| `permissionMode`  | -           | Режим доступа: `default`, `acceptEdits`, `dontAsk`, `bypassPermissions` или `plan`                                                                                                                                                                                        |
| `maxTurns`        | -           | Максимальное число агентских повторов прежде чем субагент остановится                                                                                                                                                                                                     |
| `skills`          | -           | Скиллы для загрузкм в контекст субагента в начале. Загружаетсяполный контент скилла, а не просто скилл делается доступным для призыва. Субагенты не наследуют скиллы от родительских образений.                                                                           |
| `mcpServers`      | -           | MCP  сервера доступные для этого субагента. Каждая входная точка это  так же имя сервера, которое ссылается на уже сконфигурированный сервре или встроенное определение с именем сервера в качестве ключа и полной конфигурацией сервера MCP в качестве значения          |
| `hooks`           | -           | Перехватчики жизненного цикла ограничены этим субагентом                                                                                                                                                                                                                  |
| `memory`          | -           | Область постоянной памяти: `user`, `project` или `local`. Обеспечивает межсессионное обучение                                                                                                                                                                             |
| `bacjground`      | -           | Устанавливается в true для постаянной работы субагента в фоновом режиме.                                                                                                                                                                                                  |
| `effort`          | -           | Уровень усилий, когда этот субагент используется. Переопределяет уровень усилий для текущей сессии. По умолчанию наследует уровень из родительского диалога. Опции: `low`, `medium`, `high`, `max` (только для Opus 4.6)                                                  |
| `isolation`       | -           | Устанавливается в `worktree`, чтобы запустить субагента во временном `git worktree`, давая ему изолированную копию репозитория. Рабочее дерево автоматически чистится, если субагент начинает выполнять изменения.                                                        |
| `initialPrompt`   | -           | Автоматически отправляется при первом обращении пользователя, когда этот агент работает в качестве основного агента сессии (через `--agent` или настройку `agent`). Команды и навыки обрабатываются. Добавляется перед любым приглашением, предоставленным пользователем. |

## Выбор модели

Поле model указывает какую ИИ модель должен использовать субагент. Можно указывать:
- Алиас модели - один из доступных `sonnet`, `opus` или `haiku`;
- Полный ID модеи - использует полный ID модели, такой как `claude-opus-4-6` или `claude-sonnet-4-6`;
- Inherit - использует ту же модель, что и главный диалог;
- Не указана - если не задана специальная модель, то по умолчанию используется `inherit`.

Когда Клод вызывает субагента, он может передать параметр модели для этого конкретного вызова. Клод код решает какую модель указать по следующему алогоритму:
- Смотрит в переменную окружения `CLAUDE_CODE_SUBAGENT_MODEL`, если она задана;
- Смотрит в параметр `model` для каждого вызова;
- Смотрит в заданный в описании агента параметр `model`;
- Смотрит модель основного диалога.

## Контроль возможностей субагентов

Существует три способа контролировать, что субагент может делать. Через доступ к инструментам (access tools), режимы доступа (permission modes) и условные правила (conditional rules).

### Доступные инструменты

По умолчанию субагенты наследуют все инструменты из главного диалога. Но есть инструменты, которые не будут ими унаследованы или использованы, даже если будут помещены в соответствующие блоки описания субагента (блок `tools`):
-  `Agent`;
- `AskUserQuestion`;
- `EnterPlanMode`;
- `ExitPlanMode`, кроме случаев когда субагенту доступен только `planMode`;
-  `ScheduleWakeup`;
-  `WaitForMcpServers`.

Чтобы ограничить инструменты агента нужно использовать опцию `tools` (чтобы указать доступные инструемнты) или `disallowedTools` (запрещенные инструменты). Ниже пример субагента с правами Read, Grep, Glob, and Bash. При этом ему недоступны редактирование и запись файлов, а так же использование mcp:
```markdown
---
name: safe-researcher
description: Research agent with restricted capabilities
tools: Read, Grep, Glob, Bash
---
```

Его можно переписать используя `disallowedTools: Write, Edit`. Если установлены оба параметра, сначала применяется `disallowedTools`, а затем `tools` обрабатываются для оставшегося пула. Инструмент, указанный в обоих, будет удален.

### Ограничения создания конкретных типов субагентов

Если субагент запускается как главный диалог (main conversation) с claude --agent, у него появляется возможность создавать своих субагентов используя инструмент Agent. Можно так же ограничить типы субагентов, которые может создавать агент:

```markdown
---
name: coordinator
description: Coordinates work across specialized agents
tools: Agent(worker, researcher), Read, Bash
---
```

В конфиге агент может создавать субагентов worker и researcher. При попытке создания агентом других субагентов он увидит ошибку. Для блокировки спеицфических агентов и разрешения для других нужно использовать permission.deny в настройках.

Чтобы разрешить создание любых агентов нужно поместить в `tools` инструмент `Agent`. Так же стоит полчеркнуть, что создание субагентов возможно только если агент был запущен как главный диалог,  в противном случае никакие субагентов он создавать не сможет.

### Область видимости MCP для субагентов

Используйте поле `mcpServers`, чтобы предоставить субагенту доступ к серверам MCP, которые недоступны в основном диалоге. Определенные здесь встроенные серверы подключаются при запуске субагента и отключаются при его завершении. Ссылки на строки используют соединение родительского сеанса.

Каждая запись в списке представляет собой либо встроенное определение сервера, либо строку, ссылающуюся на сервер MCP, уже настроенный в вашем сеансе:

```markdown
---
name: browser-tester
description: Tests features in a real browser using Playwright
mcpServers:
  # Inline definition: scoped to this subagent only
  - playwright:
      type: stdio
      command: npx
      args: ["-y", "@playwright/mcp@latest"]
  # Reference by name: reuses an already-configured server
  - github
---

Use the Playwright tools to navigate, screenshot, and interact with pages.
```

Чтобы полностью исключить сервер MCP из основного диалога и избежать использования контекста описаниями его инструментов, определите его здесь, а не в .mcp.json. Субагент получает инструменты; родительский разговор нет.

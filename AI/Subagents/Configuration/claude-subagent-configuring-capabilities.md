Можно контролировать действия субагентов с помощью доступа к инструментам, режимов разрешений и условных правил.

## Доступные инструменты

Агенты могут использовать любые внутренние инструменты Клод Кода. По умолчанию, субагенты наследуют все инструменты из основного диалоги, включая MCP.

Чтобы ограничить инструменты, необходимо использовать поле `tools` (список разрешенных инструментов) или `disallowedTools` (список запрещенных инструментов):

```markdown
---
name: safe-researcher
description: Research agent with restricted capabilities
tools: Read, Grep, Glob, Bash
---
```

Пример ниже использует `disallowedTools` для наследования всех инструментов из главного диалога кроме Write и Edit. Субагент сохраняет доступ к инструментам Bash, MCP и всем остальным:

```markdown
---
name: no-writes
description: Inherits every tool except file writes
disallowedTools: Write, Edit
---
```

Если заданы оба поля, сначала применяется `disallowedTools`, затем `tools` сравниваются оставшимися инструментами. Инструменты, указанные в обоих списках удаляются.

## Ограничения по созданю субагентов

Когда агнет запускается как главный поток с `claude --agent`, он может порождать субагентов используя Agent инструмент. Чтобы ограничить типы субагентов, которые могут быть созданы, необходимо использовать синтаксис `Agent(agent_type)` в поле `tools`.

```markdown
---
name: coordinator
description: Coordinates work across specialized agents
tools: Agent(worker, researcher), Read, Bash
---
```

В примере выше доступны только `worker` и `researcher` субагенты. Если агент попытается создать любые другие типы агентов, запрос завершится неудачей и агент увидит лишь доступные ему типы в своем промпте. Чтобы заблокировать конкретных агентов, пока остальные остаются доступными, необходимо использовать настройку `permission.deny`.

Чтобы разрешить создавать любых субагентов бех ограничений, необходимо использовать `Agent` без скобочек:

```markdown
tools: Agent, Read, Bash
```

Если `Agent` пропущено из `tools`, агент не может создавать других агентов. Это ограничение пренадлежит только к агентам, которые запускаются как основные потоки. Субагенты не могут создавать других субагентов, поэтому в них описанные выше настройки работать не будут.

## Область видимости MCP серверов для субагентов

Чтобы дать агенту доступы к MCP серверам, необходимо использовать поле mcpServers, которое не доступно из главного диалога. Встроенные серверы, которые здесь определены, подключаются, когда себагент стартует и отключаются, когда он оканчивает свою работу. Ссылки на строки используют соединение родительского сеанса.

Каждая запись в списке представляет собой либо встроенное определение сервера, либо строку, ссылающуюся на сервер MCP, уже настроенный в текущем сеансе:

```markdown
---
name: browser-tester
description: Tests features in a real browser using Playwright
mcpServers:
  # Inline definition: scoped to this subagent only
  - playwright:
      type: stdio
      command: npx
      args: ["-y", "@playwright/mcp@latest"]
  # Reference by name: reuses an already-configured server
  - github
---

Use the Playwright tools to navigate, screenshot, and interact with pages.
```

Встроенные определения используют ту же схему, что и записи сервера `.mcp.json` (`stdio`, `http`, `sse`, `ws`), с ключом по имени сервера.

Чтобы хранить MCP сервера полностью вне главного диалога и избегать описаний их инструментов, потребляющих контекст, следует определять их в описании, а не в `.mcp.json`. Субагент получает инструменты, родительский диалог ничего.

## Режимы доступов

Поле `permissionMode` контролирует как субагент обрабатывает промпты доступов. Субагенты наследуют контекст доступов из главного диалога и могут переписывать режимы доступов, кроме тех случаев, когда родительский режим берет приоритет как описано ниже.


| Mode                | Behavior                                                                                |
| ------------------- | --------------------------------------------------------------------------------------- |
| `default`           | Стандартная проверка доступов с промптом                                                |
| `acceptEdits`       | Автоматическое разрешение правок файлов                                                 |
| `dontAsk`           | Автоматический запрет доступов промптов (явно разрешенные инструменты все еще работают) |
| `bypassPermissions` | Пропустить разрешения промптов                                                          |
| `plan`              | Режим планирования (только чтение и изучение)                                           |

Если родитель использует `bypassPermissions`, это имеет преимущетсво и не может быть переопределено. Если родитель использует `auto mode`, субагент наследует его и игнорирует все `permissionMode` в своем описании: классификатор определяет вызовы инструментов субагента с тем же блоком и правилами, как и у родительской сессии

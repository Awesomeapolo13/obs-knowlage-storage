1) Добавить в память новое правило

Инициация документации для проекта производится командой /init. Результатом будет файл CLAUDE.md. Файл теперь будет загружаться в контекст каждый раз, поэтому лучше помещать в него информацию, которая нужна всегда, а остальную помещать в отдельные файлы документации, на которые можно ссылать в промптах. 

Можно отредактировать `CLAUDE.md` файл или использовать шорт кат (просто написать ему в консоли), описав в нем, что мы хотим от него. После отправки шортката будет создан факт, клод уточнит куда необходимо сохранить его в project memory (добавит данные в `CLAUDE.md `проекта) или в user memory (будет использовать на всех проектах, добавит в `.claude/CLAUDE.md`).  

2) Переключение режимов запросов

Глубокое мышление включается в настройках, которые вызываются нажатием `alt+t`. Такой режим будет использовать больше токенов. 

`shift+tab` - сначала включит `accept all edits`, то есть клод будет автоматически принимать все что сделает без каких либо правок. Повторное нажатие активирует plan mode, в этом режиме клод расписывает план и только после нашего согласия его реализовывает.

Лучше после проверки сделать коммит, чтобы можно было удобно откатиться к нужной версии, ведь ИИ будет накапливать ошибки в процессе выполнения задачи.

Если мы хотим установить другой режим по умолчанию для клода, необходимо это делать в settings.json, добавив `permissions.defaultMode` ключ. 

3) Контекст

Контекст - это то, что клод видит в текущей сессии: наши сообщений и его ответы, файлы прочитанные им, результаты выполнения команд, логи, дивы, вывод тестов. Конектсное окно клода около 200к токенов.

Токены это 4 символа в английском (150 к слов) или 2 символа на русском (75к слов). Поэтому клод работает эффективнее с английским языком, т.е. на английском он будет экономнее с токенами.

При переполнении контекста он начинает забывать, что было  раньше, делать ошибки и терять суть разговора.

В рамках сессии контекст ИИ постоянно нарастает, в процессе общени и накопления изменений в программе. Можно выполнить команду `/context`, которая выдаст информацию о текущем использовании контекста. Если в процессе общения контекст закончится, клод сделает автокомпакт. А именно, он сделает саммари исходя из текущего контекста, подведет небольшой итог по сделанной работе, некоторые выводы. Место после этого освободится.

Если заполнены все ячейки на картинке выше, то при выполнении следующего промпта сработает автокомпакт. Если есть понимание, что следующий промпт достаточно крупный, чтобы исчерпать контекст, то лучше заранее попросить клод сжать контекст командой `/compact`. В противном случае он сделает это сам в процессе выполнения промпта, что может сказаться на качестве выполняемой работы. Можно попросить клод показывать контекст после каждого коммита.

Так же возможно сжатие с промптом, когда мы вызываем /compact и добавляем к нему некоторые инструкции. Например, `/compact и сохрани информацию о ключевых текст кейсах`.

Если есть необходимость выполнить работу, которая не связана с текущим контекстом, то нужно очистить его через использование команды `/clear`. 

4) Мониторинг стоимости (сколько от плана потрачено, сколько осталось, сколько использовали за неделю)

Для мониторинга стоимости  существует две команды `/cost` и `/usage`.
Команда кост полезна, если используем клод по апи.
Usage же показывает сколько от дневной нормы уже потрачено, сколько использовано от недельного лимита. За этим тоже стоит следить.

5) Промпт файл

Если промпт крупный и его неудобно писать в командой строке, можно создать специальный файл. Подойдет файл в формате .md, в котором мы опишем требования к тем или иным элементам программы. Затем нужно попросить клода выполнить указанное в файле, например, `выполни @docs/prompt-add-image-description.md`. После выполнения промпт можно удалить.

6) Subagents - это миниагенты, каждый из которых создан для определенной небольшой фичи. Каждый субагент имеет свой собственный контекст и затечен под свою конкретную задачу, что позволяет им выполнять эту задачу лучше.

Для работы с субагентами переходим к команде `/agents`, где выводится список уже существующих агентов и меню для их создания. Агенты могут быть как проектные, так и глобальные (user memory, который для любых проектов). Далее можно создать его с помощью Клода, или выбрать опцию ручного создания. При содании надо написать что этот агент должен делать, например, `Агент, который должен проводить код ревью изменений, и давать советы по улучшению качества кода, с точки зрения безопасности, архитекутры и оптимизации`. Клод сделает описание агента и мы сможем воспользоваться им через явное указание, либо через указание в промпте того, что его стригерит (например на просьбу о код ревью). После создания агента мы указываем ему права на тулзы (на чтение, редактирование, выполнение и прочие).

Для прямого указания субагента, надо написать в промпте его имя `Сделай код ревью изменений с агентом code-review`.

7) Автоматизация с помощью Commands

Можно автоматизировать работу клода используя команды. Для этого создаем директорию commands. В ней мы можем создавать файлы с кастомными командами, например, code-review.md. В них нужно писать промпты, которые мы хотели бы автоматизировать, например, `Сделай код ревью изменений с агентом code-review и учти при этом: $ARGUMENTS`. В них так же можно добавлять дополнительные аргументы. Далее после перезагрузки клода, новая команда появится в его меню, как имя файла, в нашем примере это будет `/code-review`. Теперь можно вызвать её добавив дополнительную информацию `/code-review и учти что...`.

8) Работа с GitHub.

Клод умеет работать с GitHub. Например, попросить его создать пул реквест. Для этого нужно будет добавить официальную утилиту от гитхаба `gh`, в ней надо авторизоваться.  Далее нужно просто написать промпт `Сделай PR с описанием фичи в master`.  Клод сделает коммит, опишет комментарий, запушит изменения

Так же можно вставить скриншот через `ctrl+v` и клод получит ссылку на изображение, например, на скриншот бага.

9) MCP

Клоду можно указать MCP (Model Context Protocol), которыми он может пользоваться для получения информации.  MCP протокол для ИИ, необходимый для получения информации. Он позволяет делать запросы в интернет, базу данных или другим API, для уточнения и получения дополнительной информации (смотреть страницы в браузере, и прочее).

Подключение локального сервера

```shell
claude mcp add <name> <command> [args...]
```

context7 - mcp сервер, который позволяет получать актуальную документацию по библиотекам и фреймворкам, которые использует клод

playwrite-mcp - сервер, который позволяет клоду открывать браузер и делать скриншоты (все для взаимодействия с браузером).

Существует несколько способов подключения mcp серверов, с областью видимости в конкретной папке, в конкретном проекте и глобально для всех проектов.

Удалить mcp сервер

```shell
claude mcp remove <server-name>
```

10) Чекпоинты

Для отката к определенной точке генерации необходимо дважды нажать `esc`, чтобы вывести список чекпоинтов.  Каждый запрос к клоду является отдельным пунктом в этом списке. Выбрав пункт мы откатимся к состоянию проекта в этой точке.

11) Режимы

У клода есть несколько режимов, которые переключаются нажатием `shift+tab`:
- default - спрашивает о любых изменениях;
- Accept edits on - выполняет любые изменения, не спрашивая разрешения;
- Plan mode - подготавливает план и после его одобрения вносит все изменения без вопросов.

Клод реагирует на слово think. Если добавить его в промпт, то он будет думать должше, но выдаст куда более взвешенный ответ: `think < think hard < think harder < ultrathink`

Так же можно прописать настройки в спеиальный файл settings.json. Он содержит доступы, запреты, о чем нужно всегда спрашивать и прочее. Файл можно разместить как глобально, так и локально для одного проета.

12) Скилы (Skills)

По сути пользовательские команды были объединены со скилами. Например, файлы команд в директориях .claude/commands/review.md и скилов .claude/skills/review/SKILL.md оба создают новую команду /review и работают одинаково. Скилы расширяют команды дополнительными функциями: каталог для вспомогательных файлов, frontmatter для [управления тем, кто вызывает skill](https://code.claude.com/docs/ru/skills#control-who-invokes-a-skill), и возможность для Claude автоматически загружать их при необходимости.

Существуют встроенные скилы, которые в отличие от встроенных команд, основаны на подсказках. Они дают клоду подробный план действий и позволяют ему организовать работу, используя свои инструменты (порождать параллельных агентов, читать файлы, адаптироваться к кодовой базе).

- **`/simplify`** - проверяет недавно измененные файлы на повторное использование кода, качество и проблемы с эффективностью, затем фиксит их (лучше запускать после реализации какой то фичи, например, `/simplify focus on memory efficiency`);
- **`/batch <instruction>`** - параллельно организует крупномасштабные изменения в базе кода, после имени скила нужно описать , что нужно сделать, далее после анализа он разобьет работу между независимыми субагентами (от 1 до 30), изолируя их друг от друга (`/batch migrate src/ from Solid to React`);
- **`/debug <instruction>`** - устраняет неполадки текущего сеанса Claude Code, читая журнал отладки сеанса. При желании опишите проблему, чтобы сфокусировать анализ;
- **`/loop [interval] <prompt>`** - выполняет промпт с указанным интервалом, пока сессия остается открытой (`/loop 5m check if the deploy finished`);
- **`/claude-api`** - загружает справочные материалы Claude API для языка вашего проекта (Python, TypeScript, Java, Go, Ruby, C#, PHP или cURL) и справочник Agent SDK для Python и TypeScript.

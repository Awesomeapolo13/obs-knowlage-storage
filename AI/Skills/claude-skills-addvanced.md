## Внедрение динамического контекста

Синтаксис `! command` запускает консольную команду перед тем, как отправить контент скилла в Клода. Результат выполнения команды вставляется на место плейсхолдера, таким образом Клод получает актуальные данные, а не саму команду.

Этот скилл обобщает пул реквест путем получения актуальных PR-данных с помощью интерфейса командной строки GitHub. Сначала запускаются команда `!gh pr diff“` и другие команды, а их вывод вставляется в промпт:

```markdown
---
name: pr-summary
description: Summarize changes in a pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---

## Pull request context
- PR diff: !`gh pr diff`
- PR comments: !`gh pr view --comments`
- Changed files: !`gh pr diff --name-only`

## Your task
Summarize this pull request...
```

1) Каждая команда с ! выполняется (еще до того как Клад увидит что либо);
2) Результаты выполнения команд заменяют плейсхолдеры в контенте скилла;
3) Клод получает полный промпт скила с актуальными данными PR.

Чтобы включить расширенное мышление в навыке, включите слово «ultrathink» в любое место содержания навыка.

## Запуск скиллов в субагентах

Добавьте `context: fork` в оформление вашего скилла, если вы хотите, чтобы навык работал изолированно. Содержимое навыка становится подсказкой, которая управляет субагентом. У него не будет доступа к истории ваших разговоров.

`context: fork` имеет смысл только для навыков с четкими инструкциями. Если навык содержит рекомендации типа «использовать эти соглашения API» без задачи, субагент получает инструкции, но не получает никаких подсказок и возвращается без значимого вывода.

Навыки и субагенты работают вместе в двух направлениях:


| Подход                       | Системный промпт                           | Таск                      | Так загружается                      |
| ---------------------------- | ------------------------------------------ | ------------------------- | ------------------------------------ |
| Скиллы с `context: fork`     | От типа агента (`Explore`, `Plan` и т. д.) | `SKILL.md` контент        | CLAUDE.md                            |
| Subagent with `skills` field | Маркдаун тело субагента                    | Сообщение делегации Клода | Предустановленные навыки + CLAUDE.md |

В контексте: fork вы записываете задачу в свой навык и выбираете тип агента для ее выполнения. Об обратном (определении пользовательского субагента, который использует навыки в качестве справочного материала) см. Субагенты.

Для примера, этот скилл позволяет проводить исследования в разветвленном агенте Explore. Содержимое навыка становится задачей, и агент предоставляет доступные только для чтения инструменты, оптимизированные для исследования базы кода:

```markdown
---
name: deep-research
description: Research a topic thoroughly
context: fork
agent: Explore
---

Research $ARGUMENTS thoroughly:

1. Find relevant files using Glob and Grep
2. Read and analyze the code
3. Summarize findings with specific file references
```

Когда этот скилл срабатывает:
1) Создаётся новый изолированный контекст
2) Субагент получает содержимое навыка в виде промпта («Тщательно изучите $ARGUMENTS…»).
3) Поле агента определяет среду выполнения (модель, инструменты и разрешения).
4) Результаты суммируются и возвращаются в основное обсуждение.

Поле агента указывает, какую конфигурацию субагента использовать. Варианты включают встроенные агенты (`Explore`, `Plan`, `general-purpose`) или любой собственный субагент из `.claude/agents/`. Если опущено, используется универсальный (`general-purpose`).

## Ограничение доступа к навыкам Клода

По умолчанию Клод вызывает любой скилл, который не имеет включенной опции `disable-model-invocation: true`. Скиллы, которые определены в `allowed-tools`, дают Клоду доступ к тем инструментам без необходимости спрашивать разрешение на их использование, пока скилл активен и выполняет свою работу. Основные настройки доступов (permission settings), при этом, все еще определяют основное поведение для всех других инструментов. Встроенные команды, такие как `/compact` или `/init` не доступны через инструменты скилов.

Есть три пути для контроля скиллов, которые Клод может вызывать:

1) Отключение через запреты инсрументов Скиллов в `/permissions`

```shell
# Add to deny rules:
Skill
```

2) Разрешение или запрет специфическим скиллам через permission rules:

```markdown
# Allow only specific skills
Skill(commit)
Skill(review-pr *)

# Deny specific skills
Skill(deploy *)
```

Синтакси следующий: `Skill(name)` - для полного совпадения, `Skill(name *)` для префиксного совпадения с любыми аргументами.

3) Скрыть отдельные навыки добавлением `disable-model-invocation: true` в их описание (это полностью уберет скилл из контекста Клода)

Поле  `user-invocable` управляет только видимостью меню, но не доступом к инструменту навыков. Используйте `disable-model-invocation: true`, чтобы заблокировать программный вызов.

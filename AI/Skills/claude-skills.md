## Общие сведения

По сути пользовательские команды были объединены со скилами. Например, файлы команд в директориях .claude/commands/review.md и скилов .claude/skills/review/SKILL.md оба создают новую команду /review и работают одинаково. Скилы расширяют команды дополнительными функциями: каталог для вспомогательных файлов, frontmatter для [управления тем, кто вызывает skill](https://code.claude.com/docs/ru/skills#control-who-invokes-a-skill), и возможность для Claude автоматически загружать их при необходимости.

В скилах можно использовать `!`перед некоторыми командами, чтобы он не ходил по каждому пункту апи, а загружал данные команд к себе в контекст.

```markdown
## Контекст выполнения
Статус проекта: !git status
Последние коммиты: !git log --oneline -10

## Алгоритм
1. Получить полный diff: git diff HEAD
2. Определить type и scope по изменениям
3. git add — добавить только нужные файлы (не git add .)
4. Сформировать сообщение по Conventional Commits
5. Создать коммит через heredoc
6. Проверить результат: git log --oneline -1
```
git status и git log теперь выполняются до первого запроса к модели. Модель сразу видит статус и историю — и переходит к шагу 1 алгоритма (git diff HEAD).

Преимущества такого применения:
- Меньше запросов к API → экономия токенов
- Команды выполняются точно с нужными аргументами
- Алгоритм скилла становится короче и чище

Так же существуют сторонние скилы, которые можно устанавливают как сторонние пакеты. например на antropics/skills репозиторий. Для безопасности нужно следить за местом откуда скачивается скилл.

## Структура скила


1) Сам скилл, например .claude/skills/skill-name/SKILL.md. Директория перед файлом SKILL.md это наш скилл, он будет вызываться по имени этой диретории, то есть /skill-name. Файл SKILL.md является обязательной точкой входа.
2) Если есть шаблон для заполнения чего либо, можно в директории скила добавить template.md (например шаблон пул реквеста)
3) Файл reference.md, файл с детальной дополнительной документацией. То есть он загружается по необходимости, в то время как SKILL.md содержит обязательную информацию.
4) Файл examples/sample.md содержит пример ожидаемого результата. Таких файлов может быть несколько.
5) Файлы в директрии scripts (scripts/validate.sh или scripts/helper.py) содержат скрипты, которые позволяют получить данные для выполнения скила.

Можно использовать встроенные константы типа ${CLAUDE_SKILL_DIR} - это директори тикущего скилла, для обращения к тем или иным файлам в SKILL.md.

В основном файле нужно описать следующие разделы:
- Наименование скилла с коротким опписанием, что нужно сделать
- Аргументы
- Подготовка, где перечислить ссылки на скрипты с обозначением того что они должны предоставить в результате.
- Задача - описание задачи скилла (так же со ссылками на файлы)
- Можно  добавить свои заголовки для описания конкретных шагов или правил.

Структура является рекомендательной, так же как и все перечисленные выше файлы. Для каких то задач можно не использовать детальную документацию.

## Типы контента скилов

Скилы могут содержать любые инструкции, но необходимо думать о том что включать в них. Есть несколько типов контента:

**Ссылочный контент** добавляет Клоду знаний, которые он применяет в работе. Соглашения, шаблоны, руководства по стилю, знание предметной области. Этот контент работает в режиме онлайн, поэтому Клод может использовать его вместе с контекстом вашего разговора.

```markdown
---
name: api-conventions
description: API design patterns for this codebase
---

When writing API endpoints:
- Use RESTful naming conventions
- Return consistent error formats
- Include request validation
```

Контент задачи дает клоду пошаговую инструкцию для специальных действий, таких как развертывание, фиксации (коммитов) или генерации кода. Его лучше использовать частых действий, которые нужно вызвать напрямую через `/skill-name`, чем позволять Клоду самому принимать решения об их применении. Нужно добавить `disable-model-invocation: true`, чтобы Клод не запускал их автоматически.

```
---
name: deploy
description: Deploy the application to production
context: fork
disable-model-invocation: true
---

Deploy the application:
1. Run the test suite
2. Build the application
3. Push to the deployment target
```

SKILL.md может содержать что угодно, но продумывание того, как мы хотим, чтобы навык вызывался (нами, Клодом или обоими) и где мы хотим, чтобы он запускался (встроенно или в субагенте), поможет определить, что включать. Для сложных навыков также можно добавить вспомогательные файлы, чтобы сосредоточить внимание на основном навыке.

## Вараинты оформления

Можно сконфигурировать поведение скила с помошью YAML синтаксиса установленного между блоками `---` в начале файла SKILL.md

```markdown
---
name: my-skill
description: What this skill does
disable-model-invocation: true
allowed-tools: Read, Grep
---

Your skill instructions here...
```

Рекомендуктся использовать поле  description, остальные поля опциональны.

- name - имя скила, если пропущено то используется наименование директории;
- description - рекомендовано к заполнению, в нем нужно описать когда использовать этот скил, чтобы Клод мог принимать решения о его использовании;
- argument-hint - подсказка, отображаемая во время автозаполнения для указания ожидаемых аргументов. Пример: `[issue-number]` или `[filename]` `[format]`;
- disable-model-invocation - по умолчанию false, если установить в true, то предотвращает автоматическую загрузку этого скила (используется для процессов, которые нужно запускать только в ручную);
- user-invocable - по умолчанию `true`, при установке в `false` скил будет скрыт из команд, которые используются через `/`;
- allowed-tools - инструкменты, которые Клод может использовать без спроса;
- model - модель, которую необходимо использовать, когда этот скил активен;
- context - установить в fork, чтобы запускать навык субагентом с отдельным контекстом;
- agent - каким субагентом должен обрабатываться, когда `context: fork`;
- hooks - хуки привязаны к жизненному циклу этого навыка (см. отдельную гладу по конфигурации).

Так же скилы поддерживают строковое описание для динамических значений (аргументов).
- `$ARGUMENTS` - все аргументы передаваемые при вызове навыка. Если $ARGUMENTS отсутствует в содержимом, аргументы добавляются как `ARGUMENTS: <value>`;
- `$ARGUMENTS[N]` - доступ новыка к специфическому аргументу по индексу (начиная с 0 для первого аргумента);
- `$N` - сокращение для `$ARGUMENTS[N]`, например `$0` для первого аргумента или $1 для второго;
- `${CLAUDE_SESSION_ID}` - текущий идентификатор сессии, полезен для ведения журналов, создания файлов для конкретных сеансов или сопоставления результатов навыков с сеансами;
- `${CLAUDE_SKILL_DIR}` - каталог, содержащий файл SKILL.md навыка. Для навыков плагинов это подкаталог навыка в пределах плагина, а не корень плагина. Используйте это в командах внедрения bash для ссылки на сценарии или файлы, связанные с навыком, независимо от текущего рабочего каталога.

```markdown
---
name: session-logger
description: Log activity for this session
---

Log the following to logs/${CLAUDE_SESSION_ID}.log:

$ARGUMENTS
```


## Вспомогательные файлы

Навыки могут включать в себя несколько файлов в своем каталоге. Это позволяет SKILL.md сосредоточиться на самом главном, позволяя Клоду получать доступ к подробным справочным материалам только при необходимости. Большие справочные документы, спецификации API или коллекции примеров не нужно загружать в контекст каждый раз при запуске навыка.

```markdown
my-skill/
├── SKILL.md (required - overview and navigation)
├── reference.md (detailed API docs - loaded when needed)
├── examples.md (usage examples - loaded when needed)
└── scripts/
    └── helper.py (utility script - executed, not loaded)
```

Чтобы Клод знал, что нахоится в каждом файле нужно установить ссылки в SKILL.md

```markdown
## Additional resources

- For complete API details, see [reference.md](reference.md)
- For usage examples, see [examples.md](examples.md)
```

Размер SKILL.md не должен превышеать 500 строк. Все что превышает этот размер лучше  переносить во вспомогательные файлы.

## Контроль того кто вызывает скил

По умолчанию и вы, и Клод можете использовать любой навык. Вы можете ввести /skill-name, чтобы вызвать его напрямую, и Клод сможет загрузить его автоматически, когда это необходимо для вашего разговора. Два поля заголовка позволяют ограничить это:
- **`isable-model-invocation: true`** - только пользователь сможет вызвать навык, лучше использовать для скилов требующих прямого вызова, которые ИИ не должен выполнять самомтоятельно;
- **`user-invocable: false`** - только клод сможет использовать этот скил, полезно для задач, которые нужно выполнять только в фоновом режиме (например, скил legacy-system-context, который будет обхяснять как работает старая часть системы).

## Ограничения доступов к инструкментам

Блок allowed-tools указывает какими инструментами Клод может пользоваться во время использования скила. Например скилл ниже выполняется только в режиме чтения файлов.

```markdown
---
name: safe-reader
description: Read files without making changes
allowed-tools: Read, Grep, Glob
---
```

## Передача аргументов в скилы

Передача аргументов доступна через плейсхолдер `$ARGUMENTS`. Скилл ниже фиксит Гитхаб ишью по номеру и плейсхолдер подставляет все аргументы что идут после вызова скилла.

```markdown
---
name: fix-issue
description: Fix a GitHub issue
disable-model-invocation: true
---

Fix GitHub issue $ARGUMENTS following our coding standards.

1. Read the issue description
2. Understand the requirements
3. Implement the fix
4. Write tests
5. Create a commit
```

При запуске `/fix-issue 123`, Клод получает сообщение «Исправьте ошибку GitHub 123 в соответствии с нашими стандартами кодирования…».

Если же в описании скила нет плейсхолдера `$ARGUMENTS`, то все переданные в скилл аргументы добавляются в конец текущего описания.

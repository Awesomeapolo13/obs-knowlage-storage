## Общие сведения

**Горутины** — это легковесные потоки, которые реализуют конкурентное программирование в Go. Их называют _легковесными потоками_, потому что они управляются рантаймом языка, а не операционной системой. Стоимость переключения контекста и расход памяти намного ниже, чем у потоков ОС (отдельный тред потребовал бы фиксированного стека на 1 MB, а горутина имеет гибкий стек от 2 KB). Следовательно, для Go — не проблема поддерживать одновременно десятки тысяч горутин.

Конкурентное выполнение - выполняется в одном процессе, но процессор переключается между процессами. Реализуется в рамках одного CPU.
Параллельное выполнение - выполнение процессов параллельно, двумя отдельными ядрами CPU.

 Для запуска функции в горутине достаточно написать слово `go` перед вызовом функции:

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	// выведет сообщение в горутине
	go fmt.Println("Hello concurrent world")
	
	// если не подождать, то программа закончится, не успев, вывести сообщение 
	time.Sleep(100 * time.Millisecond)
}
```

При написании конкурентного кода возникают новые моменты, которые нужно учитывать: состояние гонки, блокировки, коммуникация между горутинами. Пример программы, которая работает не так, как ожидается:

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	for i := 0; i < 5; i++ {
		go func() {
			fmt.Println(i)
		}()
	}
	
	time.Sleep(100 * time.Millisecond)
} 
```

Сперва може показаться, что должны вывестись числа от 0 до 4, но на самом деле вывод будет следующим:

```shell
5
5
5
5
5
```

Все потому что _i_ передается в общем скоупе, следовательно, когда горутины будут выполняться, цикл уже закончится и _i_ будет равно _5_. В данном случае нужно передать копию _i_:

```go
package main

import (
    "fmt"
    "time"
)

func main() {
    for i := 0; i < 5; i++ {
        go func(i int) {
            fmt.Println(i)
        }(i)
    }

    time.Sleep(100 * time.Millisecond)
}
```

Вывод:

```shell
0
4
3
1
2
```

Также можно заметить, что числа вывелись не в порядке вызова. Горутины выполняются независимо и не гарантируют порядка. При необходимости последовательность в выполнении придется реализовывать самостоятельно.

Даже без старта горутины в ручную она стартует при запуске программы (или получении запроса). Если у нас несколько CPU то горутины будут выполняться параллельно, если же у нас один CPU,то конкурентно.

Чтобы не ставить таймер и не дожидаться когда все горутины завершат своб работу можно использовать sync.WaitGroup.  В него нужно добавить горутины и далее вызвать метод Wait, который будет ждать их завершения.

```go
package main

import (
    "fmt"
    "time"
    "sync"
    "net/http"  
	"net/url"
)

func main() {
    t := time.Now()  
	var wg sync.WaitGroup  
  
	for i := 0; i < 10; i++ {  
	    wg.Add(1)  // добавляем горутину
	    go func(i int, wg *sync.WaitGroup) {  
	       statusCode, err := getHttpCode(wg)  
	       if err != nil {  
	          return  
	       }  
	       fmt.Println(i)  
	       fmt.Println(statusCode)  
	    }(i, &wg)  
	}  
	wg.Wait() // ждем завершения всех горутин
	fmt.Println(time.Since(t))
}

func getHttpCode(wg *sync.WaitGroup) (int, error) {  
    defer wg.Done() // помечаем горутину как завершенную в конце функции 
  
    baseUrl, err := url.Parse("https://go.dev/")  
    if err != nil {  
       fmt.Printf("ОШИБКА %s", err.Error())  
       return 0, err  
    }  
  
    resp, err := http.Get(baseUrl.String())  
    if err != nil {  
       fmt.Println(err.Error())  
       return 0, err  
    }  
  
    return resp.StatusCode, nil  
}
```
